Математическая модель и алгоритм планирования маршрутов выездных инженеров

Комплексная архитектура решения задачи маршрутизации (VRP-TW-S-C) с временными окнами клиентов, матрицей навыков специалистов и динамическим перепланированием при инцидентах.

1 Концепция и класс оптимизационной задачи

В рамках кейса ПАО «ВымпелКом» разработана интеллектуальная система автоматической диспетчеризации («помощник диспетчера»), рассчитывающая оптимальные маршруты и поминутные графики выездных сервисных инженеров для трёх округов Москвы и Московской области (Восток, Югоцентр, Юго-восток).

С точки зрения теории исследования операций (Operations Research), задача относится к наиболее сложному NP-трудному классу:

VRP-TW-S-C

Vehicle Routing Problem with Time Windows, Skills & Capacity — задача маршрутизации транспортных средств с жесткими окнами визитов абонентов, матрицей квалификаций и лимитом вместимости оборудования.

Двухуровневая лексикографическая цель

1. Минимизация штата (ФОТ): свести к минимуму число одновременно задействованных бригад.
2. Минимизация пробега: сократить суммарный километраж и холостой ход.

2 Математическая формализация задачи

Пусть задан полный ориентированный граф дорожной сети G = (V, E), где вершина 0 обозначает районный склад/офис (депо), а вершины i ∈ {1, ..., N} соответствуют заявкам клиентов.

МАТЕМАТИЧЕСКАЯ ПОСТАНОВКА ЦЕЛЕВОЙ ФУНКЦИИ
// Уровень 1: Минимизация фонда оплаты труда (числа открытых бригад) min |{ k ∈ K : |Route(k)| > 0 }| // Уровень 2: Минимизация суммарного километража дорожного графа min ∑_{k ∈ K} ∑_{i ∈ V} ∑_{j ∈ V} c_{ij} · x_{ijk} Где: • x_{ijk} ∈ {0, 1} — индикатор перемещения инженера k от точки i к j; • c_{ij} — расстояние в километрах (Haversine геодезический расчет); • K — доступный пул сертифицированных специалистов (10-14 человек на округ).
СИСТЕМА ЛИНЕЙНЫХ И ВРЕМЕННЫХ ОГРАНИЧЕНИЙ
1. Навыки (Skills Hard Constraint): x_{ijk} = 1 &implies; S_j ⊆ Skills_k (Запрещено назначать задачу специалисту без соответствующего сертификата) 2. Временные окна клиентов (Hard Time Windows): τ_{ik} ≤ b_i, где [τ_{ik} = arr_time], [a_i, b_i] — слот клиента. start_work_i = max(τ_{ik}, a_i) (ожидание при раннем прибытии допустимо) 3. Лимит продолжительности смены: start_work_last + duration_last ≤ T_{shift_end} (21:00 / 1260 минут) 4. Динамический расчет времени перемещения (взамен статических 20 минут): t_{ij} = max(10, round(dist_km(i, j) · 2.2 + 8)) [мин]

4 Архитектура 4-проходного алгоритма (4-Pass Insertion)

Вместо плоских жадных алгоритмов, приводящих к срыву окон и перерасходу персонала, разработан иерархический эвристический конвейер:

1
PASS 1: Аварии на ТКД (Опорный скелет)
Заявки категории «Авария» распределяются только старшим инженерам с аварийным допуском. Фиксируют пространственно-временной каркас графика дня.
2
PASS 2: Новые подключения FTTB/FMC (70 мин)
Самые длительные визиты с 2-часовыми клиентскими окнами. Вставка по критерию наименьшего приращения целевой функции ΔCost с микрорайонной кластеризацией.
3
PASS 3: Локальные ремонты (Минимизация ФОТ)
Ключевое правило: 30-минутные ремонты встраиваются только в графики уже открытых бригад без привлечения дополнительных людей, ликвидируя простой.
4
PASS 4: Дозаказы оборудования (Попутная доставка)
Сверхкороткие 20-минутные задачи привязываются к уже запланированным локациям мастеров, заполняя промежуточные временные коридоры.

7 Динамическое перепланирование при инцидентах

В алгоритме реализованы три обязательных сценария событийной адаптации расписания в реальном времени:

  • 🚨 Внезапная авария: Мгновенная локальная перестройка графика ведущего инженера (Pass 1). Несрочные задачи вытесняются и передаются свободным универсалам.
  • ❌ Отмена клиентом: Вырезание заявки из маршрута с прямым стягиванием рёбер (i-1) → (i+1), что устраняет холостой пробег и сокращает время ожидания следующего клиента.
  • ⚠️ Поломка транспорта инженера: Невыполненные заявки сошедшего специалиста автоматически распределяются между соседними бригадами района с минимальным смещением графиков.
