## 🚀 Ключевые возможности

* **Трёхуровневая лексикографическая оптимизация (100% покрытие >> минимум персонала >> минимум км):**
  - **Приоритет 1 (100% выполнение):** гарантированное распределение всех заказов без искусственного сброса;
  - **Приоритет 2 (Минимизация штата):** штраф +1000 км за открытие новой бригады (на датасетах кейса — 43 бригады у Baseline против 32);
  - **Приоритет 3 (Минимизация пробега):** выбор позиций с наименьшим пробегом и полировка Google OR-Tools.
* **Мультимодальный парк инженеров:**
  - 🚗 Автомобили (35 км/ч, аварии, удалённые точки, багажник 30 ед.);
  - 🚌 Общественный транспорт (20 км/ч, метро и выделенные полосы, иммунитет к пробкам, рюкзак 18 ед.);
  - 🚲 Велосипеды / СИМ (16 км/ч, плотные микрорайоны, 14 ед.);
  - 🚶 Пешие специалисты (4.8 км/ч, шаговая доступность склада до 1.5 км, 10 ед.).
* **Реальная география:** адреса заявок и офисов геокодируются через OSM, расстояния берутся по дорожному, пешеходному и велосипедному графам OpenStreetMap — не по прямой. Доля плеч, посчитанных по графу, выводится в консоли и в API.
* **Старт из офиса округа, Подмосковье — из своего города:** московские бригады начинают смену из официальных складов билайна (ул. Юных Ленинцев, проезд Симферопольский, ул. Бирюлёвская). Для Каширы, Ступина и Домодедова по ТЗ поднимается отдельный пул с базированием в самом городе — рейсы Москва ↔ Кашира не строятся.
* **Соблюдение нормативов регламента билайн:**
  - Смена с 10:00 до 22:00 (полный охват вечерних слотов 20:00–22:00) с возможностью гибкой настройки диспетчером в интерфейсе от 08:00 до 24:00;
  - Матрица компетенций инженеров (Skills Matching);
  - Имена бригад берутся из колонки «Бригада», если она есть в файле (в синтетических датасетах её нет — тогда бригады нумеруются).
* **Предиктивный контроль рисков (SLA Risk Buffer):** цветовая индикация запаса времени (🟢 >30 мин, 🟡 15–30 мин, 🔴 <15 мин).
* **Ручное переназначение заявок (Manual Dispatch):** интерактивная передача заказа между мастерами с проверкой допустимости на лету (Live Feasibility).
* **Официальный путевой лист:** генерация и печать наряда инженера с чек-листом оборудования и подписями в 1 клик.
* **Моделирование инцидентов в реальном времени:**
  - ❌ **Отмена заявки клиентом:** мгновенное вырезание точки со стягиванием дуг $(i-1) \to (i+1)$;
  - ⚠️ **Поломка транспорта инженера:** автоматическая передача оставшихся заявок соседним мастерам;
  - 🚨 **Срочная авария на ТКД:** экстренная вставка в график старшего инженера с вытеснением несрочных задач.
* **Explainable AI (XAI):** 6-пунктовое текстовое обоснование каждого назначения для диспетчера.
* **Картография 2ГИС и Спутник:** подложка тайлов 2ГИС высокого разрешения и детальный спутниковый снимок (Esri World Imagery).
* **Экспорт результатов:** формирование подробного поминутного расписания в CSV (совместимо с Excel).

## 📂 Структура проекта

```text
bilain_hack/

│   ├── test_solver.py         # Валидность плана и полнота учёта заявок

├── README.md                  # Подробная инструкция (этот файл)

    ├── Восток / Югоцентр / Юго-восток Синтетические данные.csv
    └── Восток / Югоцентр / Юго-восток Контрольное распределение.csv
```

## 📊 Измеренные результаты на датасетах кейса

Замеры получены запуском `python3 solution.py` на синтетических датасетах, расстояния — 100% по дорожному графу OSM, план каждый раз проходит независимый валидатор (0 нарушений).

| Округ | Заявок | Бригад Baseline → Опт. | Пробег Baseline → Опт. | Км на выполненную заявку | Не распределено |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Восток** | 66 | 11 → 10 (−9%) | 255.6 → 277.1 км | 7.30 → 4.20 (**−42%**) | 0 |
| **Юго-восток** | 83 | 21 → 14 (−33%) | 514.4 → 341.4 км (−34%) | 7.14 → 4.11 (**−42%**) | 0 |
| **Югоцентр** | 56 | 11 → 8 (−27%) | 334.0 → 309.8 км (−7%) | 8.35 → 5.53 (**−34%**) | 0 |
| **Итого** | **205** | **43 → 32 (−26%)** | **1104 → 928 км (−16%)** | **7.51 → 4.53 (−40%)** | **0** |

Как читать таблицу: Baseline (FIFO) выполняет только **147 заявок из 205** и 58 оставляет нераспределёнными, оптимизатор выполняет **все 205**. Поэтому абсолютный пробег — некорректная метрика сравнения: на Востоке оптимизатор проезжает больше километров именно потому, что обслуживает 66 заявок вместо 35. Показательная величина — **пробег на выполненную заявку**, он падает на 34–42% по округам.

## 🛠 Пошаговая инструкция по установке

### Шаг 1. Перейдите в директорию проекта
Откройте терминал (Terminal / PowerShell / Bash) и перейдите в папку с проектом:
```bash
cd /путь/к/папке/bilain_hack
```

### Шаг 2. Создайте и активируйте виртуальное окружение Python
Рекомендуется использовать изолированное виртуальное окружение:

* **На macOS / Linux:**
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  ```

* **На Windows (Command Prompt):**
  ```cmd
  python -m venv .venv
  .venv\Scripts\activate.bat
  ```

* **На Windows (PowerShell):**
  ```powershell
  python -m venv .venv
  .venv\Scripts\Activate.ps1
  ```

### Шаг 3. Установите зависимости
Выполните установку пакетов из `requirements.txt`:
```bash
pip install -r requirements.txt
```

> **Примечание:** В проект встроен автономный солвер на чистом Python, который работает даже при отсутствии внешних пакетов. Пакет `ortools` из `requirements.txt` ускоряет комбинаторные вычисления на очень больших графах.

## 🗺 Подготовка географических данных (один раз, нужен интернет)

Расстояния считаются по дорожному графу OpenStreetMap. Кеши координат и расстояний уже лежат в репозитории, поэтому для запуска демо этот раздел можно пропустить. Пересобрать их нужно, если появились новые адреса:

```bash
python3 geocode_addresses.py        # адреса -> координаты (OSM Nominatim), ~15-25 мин
python3 build_osrm_cache.py         # координаты -> матрицы расстояний по графам OSM, ~2 мин
python3 embed_frontend_assets.py    # перенос координат и коэффициентов в index.html
```

`build_osrm_cache.py` в конце печатает покрытие графом по каждому датасету — должно быть 100%. Для адресов, которые геокодер не нашёл, остаётся детерминированное размещение внутри района; и бэкенд, и фронтенд считают его одинаково, это закреплено тестом `tests/test_frontend_parity.py`.

Коэффициенты извилистости, которыми считаются плечи вне графа, не подбираются вручную: `calibrate_winding_factors()` берёт медиану отношения «длина по дорогам / длина по прямой» по самому кешу.

## Варианты запуска

### Вариант A: Полнофункциональный веб-сервис (рекомендуется)
Запуск локального сервера с REST API:
```bash
python3 app.py
```
> Запускайте тем Python, в который установлены зависимости из `requirements.txt` (проверка: `python3 -c "import ortools"`). Если `ortools` в этом окружении нет, сервер предупредит об этом при старте, а кнопка **Google OR-Tools** в интерфейсе покажет, как это исправить; расчёт пойдёт встроенным 4-Pass.
После запуска в терминале появится сообщение:

```text
  Откройте браузер: http://localhost:8000

```

## 🖥 Работа с веб-интерфейсом диспетчера

1. **Загрузка и переключение файлов:**
   * При первом открытии экран пуст: перетащите любой `.csv` из `test_dataset/` прямо в окно браузера (Drag-and-Drop) или нажмите **«📁 Загрузить CSV»**.
   * Каждый загруженный файл открывается отдельной вкладкой в шапке, между ними можно переключаться.
2. **Сводка эффективности (KPI):**
   * В верхней части боковой панели отображаются ключевые показатели: количество открытых бригад, суммарный пробег, обслуженные заявки и дозаказы.
3. **Моделирование инцидентов:**
   * Выберите вкладку инцидента («❌ Отмена клиентом», «⚠️ Поломка авто», «🚨 Срочная авария»);
   * Задайте параметры (заявка, инженер, время схода или район аварии);
   * Нажмите кнопку применения — маршруты и расписание на карте перестроятся мгновенно.
   * Кнопка **«🔄 Сброс плана»** возвращает исходный план дня.
4. **Интерактивная карта:**
   * В правом верхнем углу карты расположен переключатель слоев: **🗺️ 2ГИС** и **🛰️ Спутник**.
   * Клики по маркерам и маршрутам подсвечивают адреса, временные интервалы и инженеров.
5. **Объяснение решений (Explainable AI):**
   * В карточке каждой заявки нажмите кнопку **«💡 Почему этот мастер?»** для просмотра развернутого обоснования от оптимизатора.
6. **Выгрузка расписания:**
   * Нажмите **«📥 Скачать таблицей»** в шапке, чтобы сохранить готовый поминутный график в CSV.
